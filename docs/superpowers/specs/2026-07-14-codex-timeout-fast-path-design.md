# AI-CAD Codex 超时与快速链路设计

## 问题

普通规划调用固定在 160 秒终止。当前参数化计划同时携带 `featureTree` 和由它生成的 `primitives/features` 兼容视图，提示中还固定包含完整建模 schema、最近八条消息和最多三个代码样例。多轮编辑时这些重复内容增加推理时间；一旦超过 160 秒，服务器直接返回失败且没有恢复路径。

## 目标

- 缩短多轮局部编辑请求的提示长度和正常响应时间。
- 对偶发的 Codex 超时进行一次有界恢复。
- 保留当前装配、版本和对话状态，不因超时产生半成品修改。
- 让超时参数可配置，同时保持明确的资源上限。

## 方案

新增纯函数规划上下文压缩层。参数化零件存在 `featureTree` 时，从发送给 Codex 的只读副本中删除重复的 `primitives` 和 `features`；对话历史只保留最近四条，并只保留角色、文本和图片名称。首次调用继续携带相关本地样例和 CAD 参考。

新增统一的 Codex 规划调用策略：

1. 普通请求默认最长 300 秒，图片请求默认 360 秒，均可通过环境变量调整。
2. 仅当错误被识别为进程超时时重试一次；语法错误、非零退出和无效 JSON 不重试。
3. 重试使用快速上下文：最近两条消息、最多一个本地样例，并省略非必要搜索/参考上下文，但保留完整参数化计划、当前版本和用户本轮要求。
4. 第二次仍超时时返回中文错误，说明可以缩小修改范围后重试；不修改 conversation.plan、assembly revision 或构建产物。

## 边界与安全

- 不无限重试，最多两次 Codex 进程调用。
- 不删除 `featureTree`、约束、关节、零件姿态或标准件请求。
- 新建模型仍保留完整输出 schema；已有版本的局部编辑提示采用更短的 edit-patch 专用契约。
- `runProcess` 仍负责终止超时子进程；本次不改变其他 CadQuery、FreeCAD 或网络请求的超时行为。

## 测试

- 参数化计划压缩后不包含重复兼容数组，原对象保持不变。
- 快速链路减少历史和参考内容，但保留当前版本、特征 ID 和用户消息。
- 第一次超时会重试一次并可成功返回。
- 非超时错误不会重试；连续两次超时返回稳定中文错误。
- 完整 `npm run check` 验证现有 CAD、FreeCAD、UI 和安全链路不回归。
